# PRTS DPS Lab

明日方舟“卫戍协议：盟约”推演与干员 DPS 对比页。干员属性、潜能、信赖和技能等级直接来自本地游戏 V3_1 的 `character_table` 与 `skill_table`；盟约、装备、敌人和卫戍特质同样来自本地热更新解包。

## 打开

直接双击 `index.html` 即可。也可以启动本地服务器：

```powershell
npm run serve
```

然后访问 `http://127.0.0.1:4173/`。

### 手机访问

电脑和手机连接同一 Wi-Fi 后，在项目目录运行：

```powershell
npm run serve
```

先用 `ipconfig` 查看电脑的“IPv4 地址”，然后在手机浏览器访问：

```text
http://电脑IPv4地址:4173/
```

首次运行时如 Windows 防火墙询问网络权限，需要允许“专用网络”。手机不能直接打开 `D:\...\index.html`；必须通过上面的 HTTP 地址访问，且电脑要保持开机并保持服务运行。

## 功能

- 从本期卫戍协议实际可出现的 143 名干员中任选三名，比较普攻、技能期和周期 DPS，并包含森蚺指令特殊干员“暴躁铁皮”。
- 205 个本地模组覆盖 138 名卫戍干员，支持选择三级模组属性与升级天赋。
- 每个方案都支持按干员名称搜索，输入片段后也可自动匹配。
- 支持满信赖、潜能、模组、技能等级、敌人防御与法抗。
- 完整收录当前 26 条盟约，可按名称或成员干员搜索，并配置层数、激活人数。
- 收录本地 V3_1 的 116 件装备与 74 条指令/协议，可按名称、盟约、类型和效果文本搜索。
- 装备可配置到方案 A/B/C；指令可逐条启用，常驻攻击、攻速、穿透和技力消耗参数会进入 DPS。
- 每个方案可配置“变形同构体”的配套装备，显示仅装备 DPS 与转盟约后的 DPS；目标盟约仍需处于已选激活状态。
- 自动识别干员所属盟约，只把实际命中且达到激活人数的效果带入 DPS。
- 所有盟约均展示游戏内效果描述和原始 Blackboard 参数；经济、召唤和特殊机制同样可查。
- 战况图、盟约、装备、指令和 DPS 模块都可以收起、展开或放大到全屏。
- 顶部文档目录可直达战况图、盟约、装备、指令、敌人和 DPS；搜索结果与条目都有稳定锚点。
- 战况图位于主要计算区顶部。
- 可直接选用本地解包出的 458 个卫戍协议敌人，并一键停用、改回手动防御与法抗。
- 默认使用“终极模拟”敌人：模式生命/攻击/防御倍率、攻击 `×5`、防御 `×3`、法抗 `×3`，领袖生命取游戏内终极血量表。
- 使用 60 帧固定步长逐帧模拟攻击命中、技能开启、技能持续与回转，而非只看平均值公式。
- 可充能瞬时技能按充能次数、技力回复和阻回窗口逐帧处理；点燃可复现高攻速下穿插普攻造成的非单调 DPS。
- 图表可切换到“灵巧”层数作为横轴；定量分析默认假设灵巧攻速覆盖当前全部方案，用于直接观察点燃充能周期造成的锯齿状 DPS 抖动。
- 自动估算技能攻击倍率、攻速、攻击间隔、持续时间与回转，并给出击杀时间、命中次数和技能开启次数。
- 技能倍率与段数优先读取本地 `skill_table` 的 Blackboard；每个技能可展开查看技能 ID、原描述模板和全部解包参数。
- 可手动覆盖倍率、段数、无视防御、无视法抗和伤害类型。
- 普通天赋会按本地 Blackboard 自动折算攻击、攻速、回技、初始技力、概率期望、法抗无视和固定附加伤害；阵亡、阻挡、受击、召唤等条件会明确标注为未自动折算。
- 曲线默认以实际盟约层数作为横轴，展示纯 DPS 增长；敌人保持当前终极数值不变，也可切换为随防御力或法术抗性变化。
- 图表左侧可选择一条盟约作为扫描变量；只改变该盟约层数，其余已选盟约保持当前层数，切换盟约后横轴范围同步更新。
- 切换干员时，如果当前横轴不影响该干员，会自动跟随到其有输出收益的所属盟约；“特质回技”会按当前方案选择实际相关盟约。
- 图例直接显示当前盟约配置下的终极模拟 DPS，并支持当前结果 CSV 导出。
- 独立敌人击杀计算器可查看三套方案的预计击杀时间，并计算限定时间（默认 5 秒、可调整）内所需的最低 DPS。
- 页面项目栏固定在左侧；窄屏时自动改为顶部横向项目栏。

重新抓取：

```powershell
npm install
$env:ARK_HOT_DECODED = 'D:\你的解包目录\hot-decoded'
npm run refresh
npm run extract:reference
npm run extract:ultimate
npm run extract:traits
npm run extract:operators
npm run extract:modules
npm run audit:roster
npm run audit:skills
```

`refresh` 使用本机 Microsoft Edge 绕过 PRTS 对普通 HTTP 客户端的限制，再通过 MediaWiki API 分批读取干员原始资料。`extract:reference` 从本地热更新的 `activity_table` 与 `character_table` 生成装备、指令快照；`extract:ultimate` 应用终极模拟模式倍率与领袖血量表；`extract:traits` 提取卫戍协议干员专属特质；`extract:operators` 从本地 `character_table` 与 `skill_table` 生成 143 名卫戍干员的属性、信赖、潜能、技能与天赋；`extract:modules` 从本地模组表生成三级模组数据；`audit:roster` 输出全干员技能、特质、天赋和条件机制风险统计；`audit:skills` 校验全部技能 ID、原描述模板、Blackboard 和逐帧模拟结果。写文件前会校验数量和必填文本。

## 计算边界

这是统一横向比较模型，不会为 143 名卫戍干员的全部特殊机制逐一编写模拟器。召唤物、随机目标、持续场、元素爆发和复杂天赋默认不会自动拆成独立事件；页面会保留 PRTS 原文，并在“高级参数”中提供手动覆盖。

卫戍协议数据对应当前本地 `act3autochess / V3_1`。装备与指令面板会把可识别的常驻数值参数折算为 DPS 修正；涉及触发条件、随机、召唤、经济或场地的效果会保留完整文本和原始参数，不会伪装成无条件收益。

因此，它适合快速比较常规输出技能与观察参数趋势，不应替代逐帧实战轴或具体关卡推演。
